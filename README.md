## 🙋‍♂️ Sobre mim

Comecei no **suporte técnico**, atendendo quem dava de cara com o bug. Com o tempo fui ficando mais curioso sobre *por que* aquilo quebrava do que sobre como contornar, e foi assim que cheguei em **QA**.

Hoje passo boa parte do tempo escrevendo casos de teste, automatizando fluxos com **Playwright** e **Cypress** e testando APIs no **Postman**, com uma ajuda do **SQL** quando preciso olhar os dados direto no banco.

## 🚀 Projetos em destaque

### 🎮 [Bug Vault](https://github.com/pegalvao/bug-vault) · [▶️ demo ao vivo](https://pegalvao.github.io/bug-vault/)

O jogo **Freedoom** rodando no navegador via WebAssembly, com uma suíte E2E que testa um jogo **sem nenhum elemento HTML para consultar**: tudo é pixel dentro de um canvas.

- Lê os pixels do jogo para checar HUD, movimento, tiro e troca de armas
- **Regressão visual** pixel a pixel e testes de **performance** com orçamento de boot e FPS
- Esperas por estado em vez de `waitForTimeout`, com regra de lint que proíbe pausas fixas
- Tags `@smoke`, `@perf` e `@visual`, modo stress para caçar testes instáveis
- Husky + commitlint + ESLint + Prettier, deploy no GitHub Pages via Actions

`Playwright` `TypeScript` `Page Object Model` `GitHub Actions`

### 🏢 [OrangeHRM: automação E2E](https://github.com/pegalvao/orangehrm-playwright-tests)

[![Playwright Tests](https://github.com/pegalvao/orangehrm-playwright-tests/actions/workflows/playwright.yml/badge.svg)](https://github.com/pegalvao/orangehrm-playwright-tests/actions)

Automação dos fluxos críticos de um sistema de RH real, priorizando arquitetura limpa e escalável em vez de volume de testes.

- Login (válido, inválido e isolamento de sessão), smoke test de navegação e CRUD de funcionários
- **Global setup com `storageState`** para reaproveitar a sessão e acelerar a suíte
- Credenciais via `.env`, nada hardcoded
- Testes rodando a cada commit no **GitHub Actions**

`Playwright` `TypeScript` `Page Object Model` `CI/CD`

### 📋 [Test Cases & Scenarios](https://github.com/pegalvao/test-cases-scenarios)

O lado manual do QA: casos de teste, bug reports e evidências, documentados no padrão de mercado.

- Casos de teste para o e-commerce **Sauce Demo** (login válido, inválido e usuário bloqueado)
- Templates reutilizáveis de **caso de teste** e **bug report**
- Evidências com screenshots de cada execução

`Testes funcionais` `Testes exploratórios` `Documentação`
